# Safely Integrating Five LiteRT.js Benchmark Models

**Implement the three image classifiers and Whisper Base now through pinned, data-only model descriptors, but do not claim that any public file is the artifact Google benchmarked and do not register YOLO26n as generally supported until one exact export contract and its processor boundary are pinned.** The strongest reproducible candidates are the FP32 files in `litert-community/efficientnet_b0`, `litert-community/inception_v3`, `litert-community/resnet50`, and `litert-community/whisper-base`; the first three map to `image-classification` through one generic default-signature executor, while Whisper Base reuses the existing named-signature Whisper generation adapter. YOLO26n is a real model, but Google's article also says YOLO11n elsewhere and discloses neither detector file nor head mode, so the only inspected YOLO26n `.tflite` establishes a useful post-launch contract, not launch provenance ([Google launch article](https://developers.googleblog.com/litertjs-googles-high-performance-web-ai-inference/); [YOLO26 documentation](https://docs.ultralytics.com/models/yolo26/)). The provider should preserve `LiteRtInferenceProvider.from_modelId(...)`, resolve an immutable descriptor per artifact repository, keep transport/compilation/tensor ownership shared, and dispatch only among `default-forward`, `whisper`, and a gated `yolo-detection` strategy. Exact model-local `config.json` and processor sidecars are part of the executable contract: substituting metadata from a nearby Transformers model silently changes labels or preprocessing. Every compiled model must be rejected early if tensor count, dtype, shape, or signature differs from its descriptor, and every release must pass numerical browser fixtures rather than shape-only tests. This design expands the package without turning converter-generated tensor names, Whisper constants, or an assumed DETR output format into global runtime policy.

## Public artifacts establish candidates, not benchmark identity

Google's July 9, 2026 article names `efficientnet`, `inception_v3`, `resnet50`, `whisper_base`, and `YOLO26n` in its normalized chart and links the LiteRT Community classical-model collection, but it publishes **no filenames, revisions, hashes, conversion commands, quantization modes, benchmark harness, or per-model run settings**. The linked collection contains matching repositories for EfficientNet-B0, Inception V3, ResNet-50, and Whisper Base, making them the strongest public candidates, but not hash-verifiable benchmark inputs ([Web Classical Models collection](https://huggingface.co/collections/litert-community/web-classical-models); [Image Classification Models collection](https://huggingface.co/collections/litert-community/image-classification-models)). The safe product language is therefore “support for pinned public candidate artifacts,” never “support for the exact LiteRT.js launch benchmark models.” Even `efficientnet` is an inference: B0 is the nearest collection match, but the chart omits the variant.

The baseline should pin the following bytes and verify their SHA-256 values during release preparation. FP32 is the conservative common denominator for the classifiers; compressed files are opt-in descriptor variants only when their external I/O remains FP32 or INT32. LiteRT.js 2.5.3 does not expose enough public quantization metadata to safely adapt raw INT8 I/O, so static-INT8 variants must stay unregistered even when present in a repository ([LiteRT.js tensor-type limitation](https://developers.google.com/edge/litert/web/get_started#unsupported_tensor_type)).

## Five tensor contracts require three execution strategies

The runtime contract is small but not uniform. EfficientNet and ResNet use NCHW and a `main` signature, Inception uses NHWC and `serving_default`, Whisper uses two named signatures, and the inspected YOLO export returns one channels-first prediction head. **The implementation should use direct `CompiledModel.run()` for ordinary vision models rather than hard-code any default-signature key**, because LiteRT.js makes the compiled model itself the default runner and exposes runtime details through `getInputDetails()` and `getOutputDetails()` ([LiteRT.js guide](https://developers.google.com/edge/litert/web/get_started); [LiteRT.js README](https://github.com/google-ai-edge/LiteRT/tree/main/litert/js)). Named runners are justified only where names are semantic protocol, as with Whisper's `encode` and `decode`.

Compilation must immediately compare the descriptor with runtime metadata: input/output count, rank, every fixed dimension, and dtype. Error messages should identify the descriptor, semantic name, runtime name, expected contract, and observed detail. Execution can remain positional according to descriptor `inputOrder` and `outputOrder`; this deliberately decouples stable Transformers.js names from unstable converter names such as `g0::linear` and `StatefulPartitionedCall:0`. After a run, copy each LiteRT output into an ordinary CPU Transformers.js `Tensor`, assign its semantic key, and delete every LiteRT input/output in `finally`; accelerator-backed tensor integration adds ownership complexity without helping these first models.

## Exact sidecars make pipeline mappings correct

The classifier mapping is direct only after preprocessing is exact. Each descriptor advertises `image-classification`, accepts Transformers.js `pixel_values`, invokes the default runner, and returns `{ logits }` without softmax. `ImageClassificationPipeline` already performs softmax, top-k selection, and `config.id2label` lookup, so provider-side softmax would duplicate policy and alter scores. All three model repositories need a model-local or dedicated pinned shared-assets repository containing the standard 1,000-entry ImageNet label map and the exact processor configuration; the executable repositories currently do not supply those files ([ImageNet-1K label map](https://huggingface.co/datasets/huggingface/label-files/blob/main/imagenet-1k-id2label.json)).

| Model | Required Transformers.js processor semantics | Runtime adaptation |
|---|---|---|
| EfficientNet-B0 | RGB; bicubic resize of shorter edge to 256; center crop `224x224`; rescale `1/255`; normalize with mean `[0.485,0.456,0.406]`, standard deviation `[0.229,0.224,0.225]`; base `ImageProcessor` emits NCHW | None. Do not borrow `google/efficientnet-b0`: it represents a different processor convention ([TorchVision EfficientNet-B0 weights](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.efficientnet_b0.html); [Google processor config](https://huggingface.co/google/efficientnet-b0/blob/main/preprocessor_config.json)). |
| Inception V3 | RGB; bilinear resize of shorter edge to 342; center crop `299x299`; rescale and normalize with the same ImageNet values; base processor emits NCHW | Explicit descriptor-driven transpose `[1,3,299,299]` to `[1,299,299,3]` immediately before LiteRT tensor construction ([TorchVision Inception V3 weights](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.inception_v3.html)). |
| ResNet-50 V2 | RGB; bilinear resize of shorter edge to 232; center crop `224x224`; rescale and normalize with the same ImageNet values; NCHW | None. `microsoft/resnet-50`'s current 256-edge path is not exact for this V2 export ([TorchVision ResNet-50 weights](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.resnet50.html); [Microsoft processor config](https://huggingface.co/microsoft/resnet-50/blob/main/preprocessor_config.json)). |

Whisper Base maps to `automatic-speech-recognition` through `generate()`, not generic `forward()`. Its descriptor uses `openai/whisper-base` as the shared-assets source for `config.json`, `generation_config.json`, tokenizer files, normalizer, and the 80-channel mel filter bank. Transformers.js should continue to own mono 16 kHz loading, 30-second pad/truncate behavior, 400-sample FFT, 160-sample hop, chunking/stride bookkeeping, and `_decode_asr()`; the runtime adapter runs `encode` once per feature window, builds the language/task/no-timestamps prompt, maintains the fixed 128-token buffer and causal mask, iterates `decode`, applies suppression/EOS rules, and returns token IDs ([upstream Whisper Base](https://huggingface.co/openai/whisper-base); [Whisper feature extractor documentation](https://huggingface.co/docs/transformers/model_doc/whisper#transformers.WhisperFeatureExtractor)). This is the same external protocol as the package's current Whisper Tiny implementation, with encoder width supplied by metadata rather than hard-coded. Google's chart calls Whisper Base a “Text Encoder,” so its published latency should be interpreted as encoder-subgraph latency unless benchmark code proves end-to-end transcription.

YOLO cannot be mapped to the current DETR/YOLOS postprocessor by renaming its tensor. That path expects separate class logits and normalized center-format boxes, applies softmax with a final background class, and performs no NMS; applying it to `[1,84,8400]` would corrupt class probabilities, drop a real COCO class, mis-scale pixel coordinates, and preserve duplicate boxes. A safe YOLO mapping requires RGB aspect-preserving letterbox resize/pad to `640x640`, `1/255` scaling, CHW packing, and retained ratio/padding metadata. Postprocessing selects class scores without another sigmoid or softmax, filters by confidence, converts `cx,cy,w,h` to corners, applies class-aware NMS, reverses letterboxing, clips to the source image, and returns boxes, scores, and integer labels ([Ultralytics prediction documentation](https://docs.ultralytics.com/modes/predict/)). Because preprocessing and target-size-aware postprocessing belong to the image processor in today's `ObjectDetectionPipeline`, **the runtime package alone cannot complete this mapping safely**. Registration requires either a new Transformers.js `YoloImageProcessor` selected by a model-local sidecar, or an explicit backend-interface extension that carries letterbox metadata; `onnx-community/yolo26n-ONNX` can donate its COCO labels but not its direct-resize `YolosImageProcessor` configuration ([YOLO26 ONNX config](https://huggingface.co/onnx-community/yolo26n-ONNX/blob/main/config.json); [processor config](https://huggingface.co/onnx-community/yolo26n-ONNX/blob/main/preprocessor_config.json)).

## Data descriptors keep the runtime minimal

The current `src/index.ts` combines browser-runtime loading with Whisper Tiny policy: default shared assets, filenames, capabilities, generation constants, signature names, and task validation all assume one model. The smallest reusable architecture keeps the public class and `from_modelId(artifactModelId, options)` API, resolves a descriptor in the constructor, and factors behavior by responsibility rather than architecture name. It does not need `EfficientNetProvider`, `InceptionProvider`, `ResNetProvider`, or `WhisperBaseProvider` subclasses.

```ts
type LiteRtModelDescriptor = {
  id: string;
  artifactModelId: string;
  sharedModelId: string;
  tasks: readonly ('image-classification' | 'automatic-speech-recognition' | 'object-detection')[];
  artifacts: Partial<Record<'fp32' | 'int8' | 'q8', {
    file: string;
    revision: string;
    sha256: string;
    devices: readonly ('wasm' | 'webgpu' | 'webnn')[];
  }>>;
  execution: 'default-forward' | 'whisper' | 'yolo-detection';
  inputs: readonly TensorContract[];
  outputs: readonly TensorContract[];
  inputLayouts?: Readonly<Record<string, 'nchw' | 'nhwc'>>;
  optionalConfigs?: readonly string[];
};
```

`src/descriptors.ts` should contain immutable contracts and exact repository lookup; `src/artifacts.ts` should select only device/dtype combinations explicitly listed by the descriptor and implement artifact listing, metadata, and deletion against `artifactModelId`; `src/runtime.ts` should retain one-time LiteRT loading, accelerator selection, and compilation; `src/tensors.ts` should own validation, CPU/LiteRT conversion, and the sole NCHW-to-NHWC permutation; and `src/session.ts` should execute default signatures positionally and assign semantic output names. `src/tasks/whisper.ts` should move the existing prompt, causal-mask, and greedy-generation behavior intact, parameterizing only actual descriptor facts such as maximum decode length, vocabulary size, signature contracts, and encoder dimensions. A future `src/tasks/detection.ts` can contain raw YOLO decode/NMS helpers, but it should not be activated until the corresponding core image processor and pinned export exist.

Provider capabilities must be descriptor-derived per instance: classifiers expose only `image-classification`, Whisper only ASR, and a verified detector only `object-detection`. `listModelArtifacts()` should include the selected `.tflite` plus shared `config.json`; Whisper alone adds `generation_config.json`. The existing host-supplied `getModelFile`, metadata, deletion, revision, progress, cache, and `local_files_only` behavior should remain unchanged, as should the expert `sharedModelId` and `modelFile` overrides. The artifact selector must not infer support from a generic `.tflite` suffix, silently choose quantization from any non-`fp32` dtype, or select a device-plugin artifact. These constraints preserve Whisper Tiny behavior while making policy inspectable and testable.

## Release gates turn unknowns into failures

Several facts remain unknowable from the launch material: the five benchmark hashes and revisions; whether `efficientnet` means B0; the cause of the YOLO11n/YOLO26n inconsistency; the launch detector's resolution, quantization, head mode, activation, coordinate encoding, and NMS ownership; the Whisper exporter's source and exact decoder-mask convention; and browser numerical parity on WASM, WebGPU, and WebNN. The Whisper mask is especially important because `[1,1,128,128]` proves shape but not whether masked positions require additive negative infinity or another convention. The current Tiny adapter uses negative infinity, which is a strong implementation hypothesis, not documentary proof. Likewise, YOLO exports can expose raw one-to-many `[batch,4+classes,boxes]`, end-to-end `[batch,max_detections,6]`, or graph-integrated NMS; shape inspection must choose the adapter, not the filename.

Node tests should first lock descriptor resolution, exact artifact/revision selection, task capabilities, shared-asset routing, unsupported device/dtype errors, and Whisper Tiny compatibility. Mocked compiled-model tests should then cover metadata rejection, semantic input/output ordering, Inception transposition, output copying, and deletion on every success and failure path; Whisper tests should cover both signatures, prompt defaults, suppression, EOS, length clamping, Base dimensions, and cleanup. YOLO math should be tested as pure code against a captured raw tensor on a non-square image, including letterbox reversal, thresholding, class IDs, class-aware IoU suppression, and maximum detections.

Real browser tests are the release gate. WASM must compile and numerically execute every registered artifact; WebGPU and WebNN need separate smoke tests that record `isFullyAccelerated` and expected fallback rather than assuming support from advertised capabilities. Classifier fixtures should assert stable top-k ImageNet IDs, Whisper should assert generated token sequences, and YOLO should assert boxes/classes/scores with tolerances. Tests must also log signature keys and complete input/output details, exercise repeated load/run/dispose cycles, and inject failures to expose leaked WASM/GPU tensors. Pinning revisions in descriptors is necessary but insufficient: the release record should preserve observed SHA-256, runtime version, browser versions, delegate settings, and golden outputs.

## Conclusion

The five labels do not represent five provider implementations. They reduce to **one validated default-forward executor, one reusable Whisper generation adapter, and one detection integration that crosses the runtime/processor boundary**. Treating artifact bytes, sidecars, and postprocessing as one versioned contract is what makes this extension safe; architecture names alone do not.

The practical sequence is therefore asymmetric: ship the three classifiers after publishing exact sidecars, add Whisper Base after mask and token-parity validation, and keep YOLO26n behind an explicit experimental descriptor until an exact one-to-many export, CORS-capable distribution point, custom letterbox processor, and numerical fixtures are all pinned. That sequence delivers most of the launch-model coverage without converting gaps in Google's benchmark disclosure into permanent API assumptions.
