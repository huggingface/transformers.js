# LiteRT.js launch benchmark model artifacts

## What exact artifacts and model versions did Google benchmark?

### Takeaway

The launch post verifies only the chart labels `efficientnet`, `inception_v3`, `resnet50`, `whisper_base`, and `YOLO26n`; it does not disclose filenames, revisions, hashes, conversion commands, quantization, input sizes, benchmark code, or per-model run settings. Consequently, none of the five exact benchmark artifacts is reproducibly identified. The strongest public candidates are the matching LiteRT Community repositories linked by the post, but this is an attribution inference rather than proof.

### Cited Findings

- The launch article is dated July 9, 2026 and says the comparison was run on a 2024 M4 MacBook Pro in a controlled browser environment, but provides no downloadable benchmark bundle or methodology beyond CPU and WebGPU comparisons. Its normalized-comparison chart labels are exactly `efficientnet`, `inception_v3`, `resnet50`, `whisper_base`, and `YOLO26n`. — [Google Developers Blog article](https://developers.googleblog.com/litertjs-googles-high-performance-web-ai-inference/); [chart image](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png)
- The article links the LiteRT Community “Web Classical Models” collection as its pretrained-model source. That collection directly contains `litert-community/whisper-base` and nests an image-classification collection containing `efficientnet_b0`, `inception_v3`, and `resnet50`. — [Google Developers Blog article](https://developers.googleblog.com/litertjs-googles-high-performance-web-ai-inference/); [Web Classical Models collection](https://huggingface.co/collections/litert-community/web-classical-models); [Image Classification Models collection](https://huggingface.co/collections/litert-community/image-classification-models)
- The public matching vision repositories identify the likely architectures as TorchVision EfficientNet-B0, TorchVision Inception V3 `IMAGENET1K_V1`, and TorchVision ResNet-50 V2/default weights respectively. EfficientNet's card reports the V1 checkpoint metrics 77.692/93.532; Inception's card explicitly names `Inception_V3_Weights.IMAGENET1K_V1`; ResNet's card reports 80.858/95.434, matching TorchVision `IMAGENET1K_V2`. — [EfficientNet-B0 card](https://huggingface.co/litert-community/efficientnet_b0); [Inception V3 card](https://huggingface.co/litert-community/inception_v3); [ResNet-50 card](https://huggingface.co/litert-community/resnet50); [TorchVision ResNet-50 weights](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.resnet50.html)
- The matching Whisper repository states that its artifact is an export of `openai/whisper-base`, and its embedded dimensions match the base model (`d_model=512`, vocabulary 51,865). — [LiteRT Community Whisper Base card](https://huggingface.co/litert-community/whisper-base); [upstream Whisper Base config](https://huggingface.co/openai/whisper-base/blob/main/config.json)
- The chart says `YOLO26n`, not YOLO11n. A different table in the same article says `Yolo11n`, so the article contains two different YOLO labels in two different benchmark figures. — [normalized comparison chart](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png); [classical model table image](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Classical_model_perf_1.original.png)
- The first official downloadable `yolo26n_w8a32.tflite` located in the linked Ultralytics ecosystem is a `yolo-flutter-app` v0.6.6 release asset created July 23, 2026, two weeks after the July 9 launch article. That release URL was therefore not the launch-time public source; the bytes could still match an earlier internal artifact, but no hash in the article permits that comparison. — [v0.6.6 release API](https://api.github.com/repos/ultralytics/yolo-flutter-app/releases/tags/v0.6.6); [release page](https://github.com/ultralytics/yolo-flutter-app/releases/tag/v0.6.6)

### Inferences

- `efficientnet` most likely means EfficientNet-B0 because `litert-community/efficientnet_b0` is the simplest exact-name match in the model collection linked from the article, but the chart omits `b0` and Google supplies no hash or filename. — [chart](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png); [collection](https://huggingface.co/collections/litert-community/image-classification-models); [candidate repository](https://huggingface.co/litert-community/efficientnet_b0)
- `whisper_base` most likely measures the encoder (`encode`) subgraph only: the chart categorizes it as “Text Encoder,” while the public artifact contains both `encode` and `decode` signatures. It should not be interpreted as end-to-end 30-second transcription latency. — [chart](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png); [Whisper artifact card](https://huggingface.co/litert-community/whisper-base)
- The public FP32 vision files are better benchmark candidates than their static INT8 variants because the model cards mark FP32 as GPU-supported and static INT8 as GPU-not-supported; this still does not prove which files Google timed. — [EfficientNet-B0 card](https://huggingface.co/litert-community/efficientnet_b0); [ResNet-50 card](https://huggingface.co/litert-community/resnet50)

### Gaps

- No public source found specifies the benchmark artifact SHA-256 values, exact repository revisions, quantization variants, input tensors, warmup/timed iteration counts, browser/version/flags, LiteRT.js version, ONNX Runtime Web version, thread count, or whether output readback was included.
- No public benchmark harness was found in the linked `google-ai-edge/LiteRT/litert/js` tree; the repository contains demos and a generic model tester, not the launch comparison configuration.
- The exact `efficientnet` variant remains unverified because the chart does not say B0.
- The exact YOLO file and export settings remain unverified; in particular, the chart does not identify FP32 versus quantized weights, 640 versus another resolution, or one-to-many versus one-to-one/NMS-free output.

- The FP32 vision artifacts and both Whisper files are directly fetchable, but the static INT8 ResNet model is not currently usable through LiteRT.js model I/O because LiteRT.js documents only FP32 and INT32 input/output support. — [ResNet model card](https://huggingface.co/litert-community/resnet50); [LiteRT.js input/output limitation](https://developers.google.com/edge/litert/web/get_started#unsupported_tensor_type)

## What are the signatures, shapes, dtypes, preprocessing, and output semantics?

### Takeaway

The candidate files were inspected from their TFLite flatbuffers. EfficientNet-B0 and ResNet-50 use NCHW FP32 inputs, Inception V3 uses NHWC FP32, Whisper has fixed `encode` and `decode` signatures, and the official downloadable YOLO W8A32 artifact uses NCHW FP32 I/O with raw one-to-many detections requiring host-side NMS.

### Cited Findings

- `efficientnet_b0.tflite` has signature `main`: input logical name `x`, tensor `g0::x`, FP32 `[1,3,224,224]` (NCHW); output logical name `linear`, tensor `g0::linear`, FP32 `[1,1000]`. The 1,000 values are ImageNet class logits from the TorchVision classifier, so apply softmax only if probabilities are required and rank/top-k can operate directly on logits. — [downloaded artifact](https://huggingface.co/litert-community/efficientnet_b0/resolve/2f882b5d920c156a466bcb5debae63af78d5fc08/efficientnet_b0.tflite); [model card](https://huggingface.co/litert-community/efficientnet_b0); [TorchVision EfficientNet-B0 documentation](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.efficientnet_b0.html)
- EfficientNet-B0 preprocessing is RGB, resize the shorter edge to 256 with bicubic interpolation, center-crop 224x224, scale bytes to `[0,1]`, normalize channels with mean `[0.485,0.456,0.406]` and standard deviation `[0.229,0.224,0.225]`, then transpose HWC to CHW and add batch dimension. — [TorchVision EfficientNet-B0 transforms](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.efficientnet_b0.html); [LiteRT Community usage code](https://huggingface.co/litert-community/efficientnet_b0)
- `inception_v3.tflite` has signature `serving_default`: logical input `args_0`, tensor `serving_default_args_0:0`, FP32 `[1,299,299,3]` (NHWC); logical output `output_0`, tensor `StatefulPartitionedCall:0`, FP32 `[1,1000]`. Output values are ImageNet class logits. — [downloaded artifact](https://huggingface.co/litert-community/inception_v3/resolve/8adf46014deda51d76ea19693140660c7610b65e/inception_v3.tflite); [model card](https://huggingface.co/litert-community/inception_v3)
- Inception V3 preprocessing is RGB, resize shorter edge to 342 with bilinear interpolation, center-crop 299x299, scale to `[0,1]`, normalize with ImageNet mean/std `[0.485,0.456,0.406]` / `[0.229,0.224,0.225]`, retain NHWC, and add batch dimension. — [LiteRT Community usage code](https://huggingface.co/litert-community/inception_v3); [TorchVision Inception V3 documentation](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.inception_v3.html)
- `resnet50.tflite` has signature `main`: logical input `x`, tensor `g0::x`, FP32 `[1,3,224,224]` (NCHW); logical output `linear`, tensor `g0::linear`, FP32 `[1,1000]`. Output values are ImageNet logits. — [downloaded artifact](https://huggingface.co/litert-community/resnet50/resolve/fdc3dccce8ea6021febcc7c4027c95134d9bb9d5/resnet50.tflite); [model card](https://huggingface.co/litert-community/resnet50)
- The ResNet checkpoint is the TorchVision V2/default recipe: RGB, resize shorter edge to 232 with bilinear interpolation, center-crop 224x224, scale to `[0,1]`, normalize with the same ImageNet mean/std, transpose to NCHW, and add batch dimension. — [model card usage code](https://huggingface.co/litert-community/resnet50); [TorchVision ResNet-50 V2 transforms](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.resnet50.html)
- Both Whisper files expose identical external signatures. `encode`: logical `args_0`, FP32 `[1,80,3000]` log-Mel features to logical `output_0`, FP32 `[1,1500,512]` encoder last hidden state. `decode`: `args_0` FP32 `[1,1500,512]` encoder hidden state, `args_1` INT32 `[1,128]` decoder token IDs, and `args_2` FP32 `[1,1,128,128]` decoder attention/causal mask; output `output_0` is FP32 `[1,128,51865]` vocabulary logits. — [FP32 artifact](https://huggingface.co/litert-community/whisper-base/resolve/ba2c613646edc2b72f5a51fa0b5b0b322e436101/whisper_base_30s_f32.tflite); [I8 artifact](https://huggingface.co/litert-community/whisper-base/resolve/ba2c613646edc2b72f5a51fa0b5b0b322e436101/whisper_base_30s_i8.tflite); [artifact card](https://huggingface.co/litert-community/whisper-base); [upstream config](https://huggingface.co/openai/whisper-base/blob/main/config.json)
- Whisper preprocessing expects mono 16 kHz audio, pads/truncates to 30 seconds, and extracts 80-channel log-Mel features using FFT size 400 and hop length 160, yielding 3,000 input frames. Decoding must implement Whisper generation semantics and tokenize/decode with the upstream Whisper tokenizer; taking one argmax over all `[128,51865]` positions is not an end-to-end transcription pipeline. — [Whisper feature extractor documentation](https://huggingface.co/docs/transformers/model_doc/whisper#transformers.WhisperFeatureExtractor); [Whisper tokenizer/generation documentation](https://huggingface.co/docs/transformers/model_doc/whisper); [upstream config](https://huggingface.co/openai/whisper-base/blob/main/config.json)
- The post-launch official `yolo26n_w8a32.tflite` has signature `serving_default`: logical input `args_0`, tensor `serving_default_args_0`, FP32 `[1,3,640,640]` NCHW; logical output `output_0`, tensor `serving_default_output_0_output`, FP32 `[1,84,8400]`. This is the one-to-many detection head: 4 box coordinates plus 80 COCO class scores for 8,400 candidates, requiring confidence filtering and NMS outside the graph. — [downloadable release artifact](https://github.com/ultralytics/yolo-flutter-app/releases/download/v0.6.6/yolo26n_w8a32.tflite); [YOLO26 dual-head output documentation](https://docs.ultralytics.com/models/yolo26/#usage-examples); [LiteRT export guide](https://docs.ultralytics.com/integrations/litert/)
- YOLO preprocessing uses RGB, aspect-preserving letterbox resize/pad to 640x640, scaling pixel values by `1/255`, and planar CHW packing. Raw one-to-many output box channels are center-x, center-y, width, height in model-input pixel coordinates, followed by per-class scores; reverse letterbox scaling, convert boxes to corners, threshold, and class-aware NMS for final detections. — [Ultralytics predictor preprocessing documentation](https://docs.ultralytics.com/modes/predict/); [YOLO26 output documentation](https://docs.ultralytics.com/models/yolo26/#usage-examples); [LiteRT export layout note](https://docs.ultralytics.com/integrations/litert/)
- LiteRT.js currently supports only FP32 and INT32 model inputs/outputs. Quantized weights are viable if the external interface remains FP32/INT32, as it does for Whisper I8, ResNet dynamic W8/FP32, EfficientNet weight-only W8/FP32, and YOLO W8A32. — [LiteRT.js limitation](https://developers.google.com/edge/litert/web/get_started#unsupported_tensor_type); [model repositories](https://huggingface.co/collections/litert-community/web-classical-models); [Ultralytics quantization guide](https://docs.ultralytics.com/integrations/litert/)

### Inferences

- Runtime dispatch should prefer named signatures where available and validate names, shapes, and dtypes from `model.signatures`/detail APIs. Hard-coding a universal `serving_default`, NHWC layout, or `Identity` output would fail on the public EfficientNet/ResNet artifacts. — [LiteRT.js named-signature API example](https://github.com/google-ai-edge/LiteRT/tree/main/litert/js); [EfficientNet artifact](https://huggingface.co/litert-community/efficientnet_b0/resolve/2f882b5d920c156a466bcb5debae63af78d5fc08/efficientnet_b0.tflite); [Inception artifact](https://huggingface.co/litert-community/inception_v3/resolve/8adf46014deda51d76ea19693140660c7610b65e/inception_v3.tflite)
- The launch's Whisper number should be modeled as encoder-only latency unless contrary benchmark code appears, because the chart explicitly calls it a text encoder and the encoder is independently callable. — [chart](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png); [artifact signatures](https://huggingface.co/litert-community/whisper-base)

### Gaps

- The Whisper repository does not document the exact value convention for its explicit `[1,1,128,128]` mask (for example zero versus additive negative infinity), and its generic `args_0`/`args_1`/`args_2` names do not encode semantics. The shape-based mapping above is strongly supported by upstream Whisper semantics but should be confirmed against the missing exporter source before implementing decoding.
- The YOLO launch artifact may have used a different output head or export version than the post-launch W8A32 file inspected here.
- Quantization scales/zero points for static INT8 variants should be read from each flatbuffer at runtime; they are not safely interchangeable across files.

## Is “YOLO26n” exact, a typo, or newly named, and what official LiteRT.js examples exist?

### Takeaway

`YOLO26n` is an exact, real Ultralytics model name: YOLO26 is a model family released in 2026 and `n` is its nano detection variant. It is not a typo in the normalized chart, although the article is internally inconsistent because its other benchmark table uses YOLO11n. Official generic LiteRT.js examples exist from Google, and Ultralytics now provides an official higher-level LiteRT.js browser package, but no launch-time example reproduces all five benchmark entries.

### Cited Findings

- Ultralytics documents YOLO26 as a January 2026 model family and lists detection checkpoint filenames `yolo26n.pt`, `yolo26s.pt`, `yolo26m.pt`, `yolo26l.pt`, and `yolo26x.pt`; `YOLO26n` is the nano model with 2.4M fused parameters and 5.5B FLOPs at 640 pixels. — [official YOLO26 documentation](https://docs.ultralytics.com/models/yolo26/)
- The official Hugging Face repository publishes `yolo26n.pt`, and the official LiteRT guide uses exactly `YOLO("yolo26n.pt")` and says the default export creates `yolo26n.tflite`. — [official model repository API](https://huggingface.co/api/models/Ultralytics/YOLO26?blobs=true); [official LiteRT export guide](https://docs.ultralytics.com/integrations/litert/)
- Google’s official LiteRT.js guide includes ResNet18 end-to-end preprocessing, `loadLiteRt`, `loadAndCompile`, WebGPU/WebNN options, TFJS interoperability, signature/detail introspection, and a model tester. — [LiteRT.js get-started guide](https://developers.google.com/edge/litert/web/get_started)
- Google’s official repository includes a complete MobileNetV2 browser demo that loads a public `.tflite`, performs ImageNet normalization/NCHW transpose, calls `runWithTfjsTensors`, and computes top-k results. No EfficientNet, Inception, ResNet-50, Whisper, or YOLO-specific demo is present in the repository's listed `litert/js/demos` directories. — [demo source](https://github.com/google-ai-edge/LiteRT/blob/main/litert/js/demos/mobilenetv2/src/index.ts); [demos directory](https://github.com/google-ai-edge/LiteRT/tree/main/litert/js/demos)
- Ultralytics now documents an official browser path: install `@ultralytics/yolo` plus `@litertjs/core`, then `YOLO.load('/models/yolo26n.tflite')`, `predict(...)`, and optionally `annotate(...)`. It recommends a float32 one-to-many export (`nms=None`) for WebGPU because the NMS-free head currently contains unsupported `int64`/`gather_nd` operations and falls back to WASM. — [official Ultralytics web README, LiteRT.js section](https://github.com/ultralytics/inference/blob/main/web/README.md#-litertjs-backend); [package source](https://github.com/ultralytics/inference/tree/main/web)
- Ultralytics' current browser package expects the single-file LiteRT export format from Ultralytics v8.4.83 or later and reads task/class/input metadata from the `.tflite`; GitHub release asset URLs lack browser CORS, so the model must be hosted same-origin or on a CORS-enabled origin for direct browser loading. — [official Ultralytics web README](https://github.com/ultralytics/inference/blob/main/web/README.md#-litertjs-backend)

### Inferences

- Treat `YOLO26n` as intentional in implementation naming. Treat `Yolo11n` as a separate benchmark entry in the article's accelerator table, not as evidence that the normalized chart's `YOLO26n` label is a typo. — [normalized chart](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Data_image_1600x900.original.png); [accelerator table](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/Classical_model_perf_1.original.png); [YOLO26 documentation](https://docs.ultralytics.com/models/yolo26/)
- The safest concrete YOLO implementation target today is an exported FP32 one-to-many `yolo26n.tflite` with `[1,3,640,640]` input and host-side postprocessing, rather than claiming fidelity to the undisclosed launch artifact. — [Ultralytics browser guidance](https://github.com/ultralytics/inference/blob/main/web/README.md#-litertjs-backend); [LiteRT export guide](https://docs.ultralytics.com/integrations/litert/)
